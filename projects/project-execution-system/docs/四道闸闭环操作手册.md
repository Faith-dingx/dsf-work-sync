# 四道闸闭环操作手册

> **一句话定位**：本手册是主 agent 执行任意任务的照单操作说明书。配合 P0-P5 模板使用——模板是任务载体，手册是操作规则。

---

## 一、agent 速查表（五环）

| 角色                | provider    | model                     | 职责                                                        | 何时用               | 交付标准                                                                                  |
| ------------------- | ----------- | ------------------------- | ----------------------------------------------------------- | -------------------- | ----------------------------------------------------------------------------------------- |
| **project-planner** | agnes       | agnes-2.5-flash（免费）   | P1 项目规划：读立项→定文件结构→拆 bite-sized 任务→写计划.md | 进入 P1 时           | 计划文档（文件结构 + bite-sized 任务 + 每任务验收标准 + 依赖顺序 + 风险项），只规划不实施 |
| **plan-reviewer**   | agnes       | agnes-2.5-flash（免费）   | P1 方案评审：找漏洞/遗漏/过度设计                           | 计划产出后、进 P2 前 | 评审报告（缺陷清单 + 修正建议），主 agent 确认修订                                        |
| **code-agent**      | opencode-go | deepseek-v4-flash（付费） | P2 编码实施：TDD/小步/门禁                                  | P2 执行阶段          | typecheck+lint+test 全绿，绿色状态留痕                                                    |
| **check-agent**     | agnes       | agnes-2.5-flash（免费）   | P3 独立质检：跑验证+查遗漏+查死胡同+证据反馈                | P3 验证阶段          | 质检报告（含具体 evidence），主 agent 签收                                                |

**铁律**：主 agent 只做编排（规划/派发/汇总/决策/兜底），**不亲自实施代码**。

## 二、任务决策规则

| 任务类型     | 走哪道闸         | 派谁                                                       | 说明                                                                                      |
| ------------ | ---------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **代码任务** | 五环全走         | project-planner → plan-reviewer → code-agent → check-agent | 必须派 project-planner 产出计划；必须派 plan-reviewer 审方案；必须派 check-agent 独立验收 |
| **文档任务** | 一闸（方案评审） | project-planner（可选）→ plan-reviewer                     | 规划阶段产出计划后，审文档结构/逻辑                                                       |
| **配置任务** | 一闸（方案评审） | project-planner（可选）→ plan-reviewer                     | 碰主系统（settings/profile）必须审，备份+最小改动                                         |
| **诊断任务** | 零~一闸          | 主 agent 自主                                              | 不产出代码/配置的可直接做；复杂诊断派 check-agent 复审                                    |
| **收尾记录** | 零闸             | 主 agent 自主                                              | CHANGELOG/PROGRESS/temp 归档，必须立即做                                                  |

**强制派发规则**：

- 任何编码任务：**必须派 project-planner 产出计划**（P1 规划专职），**必须派 plan-reviewer 审方案**（防"做对事做错需求"）
- 任何代码任务：P3 阶段**必须派 check-agent 独立签字**（主 agent 不能自己拍板上线）

## 三、四道闸操作步骤

### 闸口 1：方案评审（P1 → P2）

| 项目           | 说明                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| **谁发起**     | 主 agent                                                                      |
| **谁执行**     | plan-reviewer                                                                 |
| **执行动作**   | 把 `docs/计划.md` 丢给 plan-reviewer，要求：找漏洞/遗漏/过度设计/风险项       |
| **通过标准**   | plan-reviewer 输出评审报告（缺陷清单 + 修正建议）；主 agent 确认修订后进入 P2 |
| **不过怎么办** | 按评审报告修正计划，再次提交 plan-reviewer 复审，直到通过                     |
| **证据要求**   | 评审报告原文保留；修订后的计划版本对比记录                                    |

### 闸口 2：编码实施（P2 执行）

| 项目           | 说明                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| **谁发起**     | 主 agent（按计划派任务）                                                         |
| **谁执行**     | code-agent                                                                       |
| **执行动作**   | TDD：先测试 → 跑绿 → 最小代码 → 跑绿 → 重构；husky 硬卡不通过不提交              |
| **通过标准**   | typecheck + lint + test 全绿；git diff 对照验收清单逐项确认                      |
| **不过怎么办** | code-agent 自修；同一方案重试 ≥2 次失败 → 熔断换方向；卡 >15 分钟 → 回滚最近绿点 |
| **证据要求**   | 每步绿色状态留痕（命令行输出截图/日志）                                          |

### 闸口 3：独立质检（P3）

| 项目           | 说明                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **谁发起**     | 主 agent（收到 code-agent "完成"信号）                                                                                                 |
| **谁执行**     | check-agent                                                                                                                            |
| **执行动作**   | 独立跑测试 + 查遗漏 + 查死胡同 + 全局偏差；断言前先列证据                                                                              |
| **通过标准**   | check-agent 输出质检报告（含具体 evidence）；**且质检必须含"真实运行态验收"维度（见第五节），仅单元测试全绿不得判通过**；主 agent 签收 |
| **不过怎么办** | 反馈给 code-agent 修正，重跑验证；check-agent 复验直到通过                                                                             |
| **证据要求**   | 质检报告原文保留（命令输出/diff/测试日志）                                                                                             |

### 闸口 4：提交部署（P4）

| 项目           | 说明                                                  |
| -------------- | ----------------------------------------------------- |
| **谁发起**     | 主 agent（收到 check-agent "通过"信号）               |
| **谁执行**     | 主 agent                                              |
| **执行动作**   | 分支整合 → 部署 → 用户验收（功能演示 + 验收标准核对） |
| **通过标准**   | 用户签字确认；验收记录归档                            |
| **不过怎么办** | 记录未过原因，回 P3 修正重跑                          |
| **证据要求**   | 验收记录（用户确认文字/截图）                         |

## 四、验收与提交硬门槛

### 验收通过标准（必须同时满足）

1. **证据先行**：每项验收条件都有具体证据（测试通过命令输出 / diff 确认 / 截图），无"应该没问题"
2. **独立签字**：check-agent 质检报告明确结论"通过"，主 agent 不可自己拍板
3. **机器门禁**：husky pre-commit（lint+format）+ pre-push（test）全通过，不通过不提交
4. **真实运行态验收（硬性，2026-08-22 新增）**：依赖外部服务（模型网关/分类器/网络）的插件，P3 质检必须包含【真实运行态验收清单】完成记录；**任何"人工验收/真实环境验收"项未执行完毕，不得标记为已上线/已部署**（教训：guard-main-agent T10 人工验收长期挂起却被当作已提交上线，分类器故障时无差别 fail-close 锁死主 agent，属上线把关缺失）

### 上线前真实运行态验收清单（硬性，缺一不可）

> 2026-08-22 事故复盘新增：guard 分类器不可用 → fail-close 锁死主 agent 全部工具。此后**所有插件提交/部署前**，check-agent 必须逐项执行并留证据：

- [ ] **1. 正常路径真实运行**：插件在真实 dsh 进程（非单测 mock）中挂载、事件触发、产物落盘（日志/文件时间戳为证）
- [ ] **2. 外部依赖故障演练**：模拟依赖不可用（如断开/错误配置 model 网关、分类器超时），验证插件**不会锁死宿主主流程、不会静默烧钱、fail-open/降级符合设计**
- [ ] **3. 降级路径行为核验**：故障时对"只读 vs 写/执行"两类操作的处置符合预期（只读可放行、高风险须保守）
- [ ] **4. 人工验收项闭环**：计划中的用户/人工验收场景（如 T10 12 场景）逐条执行完毕并留证据；未执行完毕 → 标记"未上线"
- [ ] **5. 回归基线**：同包既有测试 + 关联包（如 guard↔injection）测试全绿

**铁律**：**没有真实运行态验收记录 = 不允许提交部署 = 任务不算完成**。

### 提交前必做清单

- [ ] CHANGELOG.md 更新（改动明细）
- [ ] PROGRESS.md 更新（进度 + 阻塞点）
- [ ] temp 文件归档（`.temp/archive/YYYY-MM-DD/`，带日期命名）或清除
- [ ] memory_log 写入今日工作流水账
- [ ] 未完成事项记录到进展.md

**铁律**：没有收尾记录 = 任务不算完成。

## 五、禁止事项

| 禁止项                                   | 说明                                                                                                                                                                 |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ❌ 主 agent 亲自实施代码                 | 代码工作一律派 code-agent，主 agent 只做编排                                                                                                                         |
| ❌ 跳过闸口                              | 四道闸是硬卡，不通过就停在当前阶段                                                                                                                                   |
| ❌ 自己拍板上线                          | 代码任务必须经 check-agent 独立质检签字                                                                                                                              |
| ❌ 配置改动不经方案评审                  | 碰主系统（settings/profile/host 等）必须先派 plan-reviewer 审                                                                                                        |
| ❌ 记忆/文档记录可省                     | CHANGELOG/PROGRESS/memory_log 必须同步更新                                                                                                                           |
| ❌ "再试一次"自欺                        | 同一方案重试 ≥2 次失败立即熔断换方向                                                                                                                                 |
| ❌ 后台任务空转不制止（2026-08-22 纪律） | 单任务运行 >15 分钟无实质进展、或同一命令/动作循环出错 ≥3 次 → 主 agent 必须**主动 job_kill 制止**，改派新方向（换思路/换更小步/换模型）尽快解决，绝不放任空转烧时间 |

## 六、与 P0-P5 的配合说明

| P 阶段          | 闸口               | 主 agent 动作                                                       |
| --------------- | ------------------ | ------------------------------------------------------------------- |
| **P0 立项**     | —                  | 主 agent 自主：brainstorming + grill-me + 写立项文档 + 用户确认     |
| **P1 规划**     | 闸口 1（方案评审） | 派 project-planner 产出计划 → 派 plan-reviewer 审 → 修订 → 用户确认 |
| **P2 实施**     | 闸口 2（编码实施） | 主 agent 派 code-agent → code-agent TDD 执行 → 绿色状态留痕         |
| **P3 验证评审** | 闸口 3（独立质检） | 主 agent 派 check-agent → check-agent 独立跑验证 → 质检报告         |
| **P4 验收部署** | 闸口 4（用户验收） | 主 agent 整合部署 → 用户验收 → 验收记录                             |
| **P5 收尾沉淀** | —                  | 主 agent 自主：CHANGELOG + PROGRESS + temp 归档 + memory_log        |
