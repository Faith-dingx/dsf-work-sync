# P0-P5 全流程模板

> **定位**：这套模板是每个任务的标准化执行载体。任何工作（代码/文档/配置/调研）都从 P0 走到 P5，四道闸在每个阶段入口卡住。

---

## P0 立项

**目标**：明确"做什么、为什么做、边界在哪"，形成可追溯的立项文档。

**要做**：

- [ ] brainstorming：发散需求、技术路线、风险点，不限定框架（15min 内）
- [ ] grill-me：主 agent 自我拷问——这问题真存在吗？解决方案是否过度设计？有没有更简单的做法？
- [ ] 写立项文档：背景/目标/范围（做 & 不做）/核心设计/验收标准/里程碑
- [ ] 提交用户确认（口头或文字回复）

**产出物**：`docs/立项.md`（项目目录内）

**检查点 / 闸口**：无立项文档不进 P1。**主 agent 不得跳过此步直接开工。**

---

## P1 规划

**目标**：把立项拆解成 bite-sized 任务，每任务有验收标准，文件结构先定。

**要做**：

- [ ] 定文件结构（目录树、主要文件名）
- [ ] 拆 bite-sized 任务（每个任务 ≤ 30 分钟可完成）
- [ ] 每个任务写验收条件（绿：typecheck/lint/test 全过；红：不通过不继续）
- [ ] 写计划文档 `docs/计划.md`（任务清单 + 依赖顺序 + 风险项）
- [ ] 提交用户确认

**产出物**：`docs/计划.md`

**检查点 / 闸口**：未确认不进 P2。**方案评审 agent 介入**：把计划丢给 plan-reviewer，找漏洞/遗漏/过度设计，修正后再进 P2。

---

## P2 实施

**目标**：TDD + 小步快跑，每步验证通过后才往下走。

**规则**：

- TDD：先写测试 → 跑测试（绿）→ 写最小代码 → 跑测试（绿）→ 重构
- 一次只做 1 个 bite-sized 任务，不过立即修
- 大文件禁全文读：grep/lsp 定位 + 分段 read
- worktrees 隔离（复杂多分支任务时）
- 死胡同熔断：同一方案重试 ≥2 次失败 → 立即换方向
- husky 硬卡：pre-commit（lint+format）、pre-push（test）不通过不提交

**要做**：

- [ ] 创建 todo 清单（每个任务一条，dsh 自动注入）
- [ ] 按 bite-sized 顺序执行，每步跑 typecheck + lint + test
- [ ] 阶段性推进进展.md

**产出物**：代码/文档，绿的状态留痕

**检查点 / 闸口**：不合格提交被 husky 拦截，**机器门禁不靠自觉**。

---

## P3 验证评审

**目标**：独立于实施者之外验证产出，确保证据先于断言。

**规则**：

- verification 铁律：**断言前先列证据**（命令输出、diff、测试日志），不说"应该没问题"
- self-review：实施者先自查一遍（对照验收清单）
- 外部评审：派 check-agent 独立跑测试 + 查遗漏 + 查死胡同 + 全局偏差
- Semgrep 静态质检（代码任务）

**要做**：

- [ ] 实施者 self-review：逐条核对 P1 验收清单
- [ ] 派 check-agent 独立复审（工具 + 证据反馈）
- [ ] 收集 check-agent 反馈，修正后重跑验证
- [ ] Semgrep 跑通（代码任务）

**产出物**：check-agent 报告（含具体 evidence），修正闭环记录

**检查点 / 闸口**：清单全过才进 P4。**独立监督 agent 签字确认**，不可自己拍板。

---

## P4 验收部署

**目标**：分支整合、部署、用户验收，确保"交付物能用"。

**要做**：

- [ ] 分支整合决策（merge/rebase，视项目规范）
- [ ] 部署（如需）
- [ ] 用户验收（功能演示 + 验收标准核对）
- [ ] 验收记录（过 / 不过 + 原因）

**产出物**：部署产物 + 验收记录

**检查点 / 闸口**：验收不过不交付。**用户确认**是硬性闸门。

---

## P5 收尾沉淀

**目标**：不留悬案，所有产出落盘可追溯。

**要做**：

- [ ] 更新 CHANGELOG.md（改动明细）
- [ ] 更新 PROGRESS.md（进度 + 阻塞点）
- [ ] project-checklist 复核：立项/计划/进展是否一致？未完成事项是否记录？
- [ ] 归档临时文件（.temp/archive/ 带日期）
- [ ] memory_log 写入今日工作流水账（跨会话可查）

**产出物**：最新 CHANGELOG + PROGRESS + 归档文件

**检查点 / 闸口**：记录未完成不算完。**没有收尾记录 = 任务不算完成**。

---

## 三层保障机制嵌入说明

| 保障层       | 载体                                | 嵌入位置                                   |
| ------------ | ----------------------------------- | ------------------------------------------ |
| **机器门禁** | husky / 测试 / 阶段脚本             | P2（pre-commit/pre-push）、P3（test 跑通） |
| **系统注入** | 记忆规则 / todo / goal 每轮强制可见 | P0~P5 每阶段开始时由 dsh 自动注入          |
| **独立监督** | check-agent / plan-reviewer         | P1（方案评审）、P3（质检复审）             |

> **语言→设备原则**：凡能用机制表达的，不用自觉。四道闸不是建议，是硬卡——不通过就停在当前阶段。
