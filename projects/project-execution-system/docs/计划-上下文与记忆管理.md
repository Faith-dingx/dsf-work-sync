## 两插件边界

| 插件                                               | 职责面        | 作用对象                                                | 触发时机                             | 核心机制                                                                                                                  |
| -------------------------------------------------- | ------------- | ------------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| **注入管理器**（dsh-injection-manager，T1-T6）     | **读/注入面** | assembly.sections / assembly.contexts / assembly.tools  | system-prompt/assemble 事件          | 按 name 判 short-term/long-term，**静态过滤 tools 列表**（5留10裁，全局统一），同名去重，异常 fail-open 返回原始 assembly |
| **写入入口插件**（dsh-memory-write-entry，T7-T11） | **写/修改面** | MEMORY.md / USER.md / 当日日志 / 近期反思 / CALENDAR.md | 任何通过 memory_write 工具发起的写入 | 白名单路径校验 + 基础格式扫描 + 审计日志，异常 fail-open 直接落盘并记警告                                                 |

**关系图**：

```
模型
  ├─→ 读工具（5个保留，全局常驻） ──→ 注入管理器决定哪些短期段进上下文
  ├─→ memory_write（写入入口唯一工具） ──→ 写入入口插件校验 + 审计 + 落盘
  └─→ 现有插件工具（10个写入工具已被注入管理器裁掉，不可见，所有agent统一）
        ↓（注入管理器从 tools 列表移除）
       模型无法直接调用这些工具

现有插件后台自动写（不经过 memory_write）：
  ├─→ auto-memory：turn-stopping 回调 → consolidateTurn() → appendText(log/notes/user)
  └─→ persona-memory：turn/end 回调 → runLearning() → store.add()
      （无法强制拦截，仅审计日志记录）
```

## 二、关键设计决策

### 决策1：记忆工具裁剪——静态固定集合，全局统一（用户规则1，v11 修正）

**不再按任务类型动态裁剪**，改为最简单方式：**5 个读取工具固定保留，10 个写入工具固定移除**。

**保留进上下文**（全局常驻，所有 agent 可见）：5 个读取工具

```typescript
const READ_ONLY_TOOLS = [
  'memory_read',
  'memory_recall',
  'memory_search',
  'memory_status',
  'calendar_list',
];
```

**裁掉**（从所有 agent 的模型可见工具列表移除）：10 个写入工具

```typescript
const WRITE_TOOLS_TO_CUT = [
  'memory_log', // auto 写日志
  'memory_note', // auto 写项目笔记
  'memory_user', // auto 写用户记忆
  'memory_reflect', // auto 写反思
  'memory_consolidate', // auto 自动沉淀
  'memory_maintain', // auto 30天蒸馏
  'memory_external', // auto 外部记忆接入
  'calendar_add', // 日历添加
  'calendar_done', // 日历完成
  'calendar_remove', // 日历删除
];
```

**实现方式**：在 `system-prompt/assemble` listener 中，过滤 `assembly.tools` 数组，硬编码移除 `WRITE_TOOLS_TO_CUT` 中的工具名。**无 classifier、无任务类型分组、无动态逻辑**。详见 v9 T2。

---

### 决策2：记忆文件分层判定——短期管理、长期不管理（用户规则2，v9 延续）

**要管（短期，直接影响上下文）**：

- `MEMORY.md` — 项目级长期笔记
- `USER.md` — 用户级长期记忆
- 当日/最近日志（`.dsh-memory/YYYY-MM-DD.md`）
- 最近的反思（`.dsh-memory/reflections/YYYY-MM-DD.md`）

**不管理（长期预存，不参与注入）**：

- 归档（`.dsh-memory/archive/`）
- 完整历史日志、完整反思库
- 长期备份

详见 v9 T3。

---

### 决策3：极简合并——同名段只留一份（v9 延续）

遍历 assembly.sections + assembly.contexts，按 name 顺序遍历，同名只保留第一次出现。不做 hash、不做内容合并、不做优先级取舍。详见 v9 T4。

---

### 决策4：实现载体——新建两个独立插件，不扩展 skill-router（v9 + v10 新增）

**理由**：

- skill-router 的职责是"技能路由"，职责边界清晰
- 记忆注入管理和记忆写入管理是独立关切，不应耦合
- 失败隔离：任一插件挂了不影响另一插件

**插件清单**：

| 包名                                  | 职责                                   | 挂载点                 |
| ------------------------------------- | -------------------------------------- | ---------------------- |
| `@deepseek-ai/dsh-injection-manager`  | 读/注入面（5读留10写裁 + 分层 + 去重） | system-prompt/assemble |
| `@deepseek-ai/dsh-memory-write-entry` | 写/修改面（唯一写入口 + 审计）         | tools 注册             |

---

### 决策5：写入入口插件——统一写工具 + 审计 + fail-open（v10 新增）

#### 5.1 模型调用写路径

注入管理器已裁掉 10 个写入工具（`memory_log` 等），模型无法直接调用它们。写入入口插件提供**唯一写入工具 `memory_write`**，模型通过此工具进行所有记忆文件修改：

```typescript
interface MemoryWriteInput {
  action: 'append' | 'replace';
  target: 'log' | 'notes' | 'user' | 'reflection' | 'calendar';
  date?: string; // YYYY-MM-DD，缺省今天
  content: string; // 写入内容
}
```

**参数说明**：

- `target=notes` → 写项目笔记 MEMORY.md（`{ws}/.dsh-memory/MEMORY.md`）
- `target=user` → 写用户级记忆 MEMORY.md（`~/.dsh/memory/MEMORY.md`）
- `target=log` → 写当日日志（`{ws}/.dsh-memory/YYYY-MM-DD.md`，append）
- `target=reflection` → 写反思（`{ws}/.dsh-memory/reflections/YYYY-MM-DD.md`）
- `target=calendar` → 写日历（`~/.dsh/memory/CALENDAR.md`）
- `action=append` → 追加（日志/笔记常用）
- `action=replace` → 整体替换（反思/日历常用）

#### 5.2 校验/审计

写入入口插件在落盘前做两件事：

**① 路径白名单校验**：

```typescript
const ALLOWED_TARGETS = ['log', 'notes', 'user', 'reflection', 'calendar'];
// 解析出绝对路径，确认在白名单目录内（~/.dsh/memory/ 或 {ws}/.dsh-memory/）
```

**② 基础格式扫描**（与 auto-memory 卫生守卫对齐，复用相同函数）：

- 乱码检测（mojibake density）
- 重复行检测（stutter）
- raw JSON envelope 检测
- base64 残骸行检测
- 单条内容超 8000 字则截断

**③ 审计日志**：
每次写入请求记录一条日志到 `{ws}/.dsh-memory/write-audit.log`：

```
[2026-08-21T14:32:00Z] target=log date=2026-08-21 content_hash=abc123 status=ok source=model
[2026-08-21T14:35:00Z] target=user date=2026-08-21 content_hash=def456 status=ok source=auto-memory-turn-stopping
```

#### 5.3 fail-open

写入入口插件异常时（插件崩溃/工具调用失败），自动降级为"直接落盘 + 记警告日志"，**不阻断记忆写入**：

- 工具调用异常 → 插件 catch → 返回错误给模型 → 模型可重试
- 插件进程崩溃 → 工具不可用 → 现有插件后台自动写仍正常工作 → 审计日志持续记录

#### 5.4 后台写路径声明（重要约束）

经对现有插件源码的完整调研，以下写路径**无法被写入入口插件强制拦截**：

| 插件           | 写路径                                           | 触发事件                          | 原因                             |
| -------------- | ------------------------------------------------ | --------------------------------- | -------------------------------- |
| auto-memory    | `consolidateTurn()` → appendText(log/notes/user) | `agent/turn-stopping`             | 插件内部方法，无 Cordis 事件钩子 |
| persona-memory | `runLearning()` → store.add()                    | `session/event (turn/end)`        | 同上                             |
| persona-memory | `saveCorrection()` → store.add()                 | `session/event (feedback/record)` | 同上                             |

**根因**：

1. 现有插件为预编译闭源 JS（npm registry 包），源码不可改
2. Cordis 框架无"写文件前拦截"事件，无法在框架层面 hook
3. 用户硬约束："任何之前运行的记忆系统都不需要禁用任何配置"，排除禁用插件方案
4. 配置文件修改方案（如改 auto 的 userMemoryDir）会被视为"修改现有配置"，违反用户约束

**替代方案**：写入入口插件提供定期扫描功能（每轮 pre-step），读取审计日志中 `source=auto-memory-turn-stopping` 的条目，向主 agent 报告"有后台写入发生但未经过 memory_write 入口"。这是只读观察，不阻塞任何操作。

#### 5.5 必须让用户决策的点

> **决策点（仅 1 个）**：是否允许对 auto-memory 做一次性的配置文件修改？
>
> 当前方案下，auto-memory 的 turn-stopping 后台写路径**不经过**写入入口插件。若希望所有写都经过入口，需要修改 auto-memory 的配置文件（`~/DSH_HOME/dsh-auto-memory.json`），将其写入路径指向写入入口插件管理的暂存区（由插件异步同步到最终位置）。这需要：
>
> - 修改 auto-memory 的 `userMemoryDir` 和 `projectMemoryDir` 配置项（指向新的暂存目录）
> - 写入入口插件负责将暂存区内容同步到原目录
> - 插件本身配置**不改**（零禁用），只是改变其写入目标
>
> **若不改配置**：后台写入绕过入口，仅在审计日志中记录，不影响主流程。
> **若改配置**：所有写（包括后台）都经过写入入口校验。
>
> **建议**：先按"不修改配置、仅审计"方案实施（零风险），后续视需求再评估是否需要改配置。

## 七、回滚方案

### 回滚注入管理器

2. 重启 dsh
3. 验证 persona/auto 插件功能完全恢复原状

### 回滚写入入口插件

2. 重启 dsh
3. 验证 memory_write 工具消失

### 完全回滚

同时移除两个插件配置行 → 重启 dsh → 系统完全恢复安装前两插件的状态。

**回滚影响**：零。两个插件是完全独立的插件，不参与任何写入操作，不影响任何现有插件。
