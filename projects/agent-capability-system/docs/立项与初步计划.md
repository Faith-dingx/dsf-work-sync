# 立项与初步计划：Agent 能力路由与双 Agent 协作体系

> 日期：2026-08-19 | 状态：立项（初步计划，待讨论实施）

---

## 一、背景与问题

模型做代码工作时的 4 大高频顽疾：

1. **丢三落四**：遗漏需求/细节/改动。
2. **大文件检索及修改困难**：上下文有限，大文件定位难、改不动。
3. **进死胡同而不自知**：在错误方向上越走越远，不自查。
4. **陷细节忽略全局**：陷入局部，丢失整体视角。

现有保障（已建）：记忆规则（每轮注入）、todo/goal、lsp、subagent、husky 门禁、TDD 流程。但**"skill 按任务自动注入"目前靠主模型自判，不可靠**（可能误判、无关 skill 干扰）。

## 二、目标

1. **skill-router**：用**辅助模型**判断当前任务该注入哪些 skill，主模型只看到被选中的（源头隔离无关 skill）。
2. **代码 Agent**：专设代码执行 Agent（能力隔离：只挂代码相关工具/skill/模型）。
3. **监督质检 Agent**：独立监督执行 + 质检（解决"死胡同不自知""细节迷失全局""丢三落四"）。
4. 与现有保障体系（记忆规则 / 门禁 / TDD 流程）整合，形成**机制自动**的代码工作保障。

## 三、范围

**做**：

- skill-router 插件（辅助模型分类 → 过滤 skill 注入）
- 代码 Agent preset（工具/模型/skill 集）
- 监督质检 Agent preset（监督/质检清单/介入时机）
- 双 Agent 协作流程协议（并行/串行、反馈闭环）
- 与现有体系整合与验证

**不做**（明确排除）：

- 模型升级策略（用户自行管理）
- 飞书/浏览器自动化（后续项目）
- 通用工具安装（已完成）

## 四、核心设计（初步）

### 4.1 skill-router

- 形态：cordis 动态插件（`skill-router`）。
- 流程：监听每轮任务事件 → 调辅助模型（9888 agnes-2.5-flash，免费）分析任务类型 → 输出应注入的 skill 清单 → 挂钩 skill catalog / system-prompt，只注入选中的。
- 判断方：**辅助模型**（非主模型自判）——判断专注、主模型不被干扰、免费零成本。

### 4.2 代码 Agent

- 角色：专注代码执行。
- 工具：lsp / 语义搜索 MCP / TDD / 代码 skill / 门禁。
- 模型：v4-pro（更强代码，已配置可用，用户掌控升级策略）。

### 4.3 监督质检 Agent

- 角色：独立监督执行（不"当局者迷"）。
- 职责：盯死胡同（轮数/时间熔断）、查丢三落四（清单核对）、全局视角（对照计划）、质检代码（标准/测试）。
- 介入：阶段检查点 + 执行末尾评审。

### 4.4 协作流程

- 代码 Agent 执行 → 监督质检 Agent **并行**盯 / 阶段质检 → 反馈 → 代码 Agent 修正 → 闭环。
- 串行环节（依赖链）：TDD（测试→实现→验证→提交）由代码 Agent 内执行，监督 Agent 验证。

## 五、验收标准（初稿）

1. 聊计划/文档时，**不会**被注入代码 skill（skill-router 隔离生效）。
2. 做代码时，相关辅助（lsp/语义搜索/TDD/评审）自动可用。
3. 监督质检 Agent 能发现死胡同 / 遗漏 / 全局偏差，并反馈闭环。
4. 双 Agent 协作流程可跑通（含阶段质检 + 末尾评审）。
5. 现有保障（门禁/记忆规则/流程）不受破坏。
