### 1.2 市场缝隙

**红海（不竞争）**：单点 LLM 网关（rholl/one-api 等）、记忆管理（Dendron/Roam 等）、护栏框架——均已成熟且开源竞争充分。

**缝隙（用户已确认定位）**：

- **中文语境私有化整体方案**——把硬件（ImmortalWrt 网关）+ 软件（Hermes/dsh agent + 模型路由 + 记忆护栏）+ 服务（部署运维）打包为一个"插电即用"的局域网 AI 网关。
- **内容引流 → 抢部署/定制单**——通过 B 站/公众号发布部署教程、评测、场景案例，吸引有类似需求但技术能力有限的用户，转化为付费部署或定制服务订单。
- **多端无缝接入**——通过手机浏览器即可直接接入任意一个 dsh 对话（无缝、无需装 app、任意浏览器即开即用）；当前各 agent 平台普遍不具备此能力，作显著差异化卖点（用户已确认）。

**夹缝定位**：本产品处于市场夹缝——大厂忙于大众市场、不做细节定制；而接受定制的精准小众群体付费意愿与黏性高。策略：小而稳、精准高价——以部署/运维/定制收费为主，不与硬件低价竞争。

### 1.3 时机判断

## 二、目标

### 2.1 终局产品

**"插电即用的局域网 AI 网关"**——任意 x86 电脑 / U 盘启动，即是一套完整的：

- 网络层：ImmortalWrt（路由 + DHCP + DNS）
- 管理层：综合面板（所有服务聚合于中文 UI）
- AI 层：模型路由 + Hermes/dsh agent（多轮对话 + 工具调用 + 记忆 + 护栏）
- 可靠层：三盘热备（坏了能就地救回，A/B 双引导）
- 存储层：AList 聚合网盘 + SMB 共享
- 载体：U 盘可复制量产，任意 x86 PC 即可启动

### 2.2 商业路径

```
插件逐个固化 → 整盘出厂镜像 → demo 视频引流 → 抢首批部署/定制单
```

## 五、开发哲学

**插件化增量**——每个功能独立固化完善，不一揽子整体开发。

> 理由：① 每完成一个插件即是一个可交付子产品，降低交付风险；② 部件稳定后才做整盘镜像，避免"半成品打包"；③ 与 OpenWrt 本身插件化基因天然契合；④ dsh 四插件流程已预演此模式。

**正确顺序（不可颠倒）**：

```
逐个部件固化稳定（各插件通过测试+提交+稳定运行≥7天）
    ↓
部件基本完善（P1-P8 核心完成）
    ↓
整盘出厂镜像（密钥剥离 + 首启引导 + 版本管理）
    ↓
发布物 + 内容引流（demo 视频 + 教程 + 接单流程）
    ↓
服务器 + 定价
```

严禁"先整盘镜像再补部件"。

**防抄袭时序**：先固化成品（可交付物）再对外推思路/内容，避免思路泄露被他人抢做。
