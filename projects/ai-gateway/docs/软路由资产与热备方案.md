## 三、系统热备方案（高可用核心资产）

> 项目：`/mnt/hermes/work/projects/系统热备方案/`（PLAN.md / 镜像制作手册.md / CHANGELOG.md / archive/）

- **目的**：整块系统盘克隆 + 双引导冗余，随便折腾都能就地或换盘救回
- **分层**：主盘双引导 overlayA(日常)/overlayB(稳定快照)；同款 32G U 盘(sdc 在线克隆镜像盘) + 120G SSD(sdb 互备启动盘)，三盘同构可互相克隆换盘
- **关键铁律**：boot=#1、bios_grub=#2（GPT 编号，非物理顺序）；每盘 UUID 全量重指向自己；rom 层 fstab 指本盘 overlay；Hermes 自启指 /mnt/hermes；同 UUID 克隆盘严禁与原盘同插
- **现状**：sdc/sdb 均独立可启动（含 Hermes + A/B 双引导）；已产出 system_backup.img / system_backup_fixed2.img.gz；待补：data 区填充、换插独立启动实测、Hermes 会话库增量同步
- **教训（防复发）**：镜像"数据层验证通过"≠"能启动"，构建后必须 `sgdisk -p` 核对分区顺序；80_mount_root 的 A→B 双引导 UUID 最易漏；同 UUID 盘同插互扰

## 四·B、开发哲学：插件化增量（2026-08-23 用户定调）

- **原则**：每个功能 = 独立插件，不整体开发，一个插件一个插件地开放、完善、发布（OpenWrt 本身就是插件化系统，天然契合；dsh 侧的 4 个插件已演示同一模式）
- **功能插件地图（候选）**：网关门户(面板) / 模型路由+监控 / Hermes 管理 / dsh 接入(含 4 插件) / 热备管理 / 存储(AList/SMB/Lucky) / 终端(ttyd) / LuCI 网络 / 音乐电视 / 对外发布与更新(opkg 源)
- **两层插件生态**：OpenWrt opkg 包层（系统服务/LuCI UI）+ dsh 应用插件层（agent 能力）——产品 = 基础镜像（核心 opkg 已含）+ 可叠加的 dsh 插件
- **工作台对接**：软路由插件化开发直接复用 dsh 工作台（五环/四道闸/真实运行态验收），一个功能一个立项闭环
