# 3081 完整入口：现象专项记录（2026-08-23）

> 目的：dsh Web 出现"3080 受限 / 3081 全功能"双端口差异，对我们是有用功能。**留档所有相关改动状态与排查预案**，若日后 3081 失效，按此恢复线索定位。

## 一、现象（已实测铁证）

- 同一 dsh 进程（本机 PID 656011，`dsh web --port 3080`）**同时监听 3080(fd21) 与 3081(fd33)**，同为 0.0.0.0，返回同款 Web（DSH Local Build）。
- **3081（完整面）**：局域网（10.10.10.9:3081 等）访问**全功能**，含记忆/配置管理接口可读写；**无 /api 信任围栏**（hostile Host → HTTP 200 直通）。
- **3080（受限面）**：带信任围栏（受信来源 → 200 writable:true；hostile → 403；记忆类 settings RPC 有 loopback-only 写保护）。局域网管理记忆 → `forbidden: loopback-only`。
- 结论：**单用户私网环境下，用 :3081 作完整主入口**（对话+记忆+配置）；:3080 备用/受限对外。**已知安全隐患：3081 无围栏，LAN 任意设备可达全功能**——多设备/对外时须加受信主机或认证（config-ui token 可承担）。

## 二、可能关联的"我们对原厂的改动"（排查时逐项核对）

所属分支：feature/lan-access（deepseek-harness，基于官方 rc.8 / b150a551 之上约 15+ 提交）

| 改动                                                        | 位置                        | 是否可能影响 3081/围栏                  |
| ----------------------------------------------------------- | --------------------------- | --------------------------------------- |
| LAN 访问改造（bind 0.0.0.0、trusted-host 受信主机）         | 早期 lan-access 补丁 + 提交 | ⚠️ 高概率相关（受信面/围栏逻辑）        |
| Web UI 相关 3 项（settings 镜像持久化、web 修复、LAN 页面） | feature/lan-access 提交     | 中                                      |
| 4 个扩展插件（guard/injection/memory/skill-router）         | packages/extensions/*       | 低（不直接管端口）                      |
| 运行配置：settings.yaml、profiles/web/cordis.patch.yml      | ~/.dsh                      | 可能有 webserver/端口相关项（排查首查） |

## 三、3081 失效时的排查预案（按序）

1. `ss -tlnp | grep -E ':308[01]\b'` —— 确认双监听是否仍在、是否同 PID（若 3081 消失 → 进程侧变化）。
2. 核对启动参数仍带 `--trusted-host`（失去它可能改变围栏/端口行为）。
3. 对比本记录第一、二节：把最近变更过的东西（升级 dsh、改 settings/profile、重打包）逐项回滚验证。
4. 查 `examples/web-cordis/cordis.yml`(port 3081) 与 `scripts/demo-cordis.mjs`——3081 曾为 demo/内部门户端口约定，若上游行为变化会在此暴露。
5. 回看 lan-access 补丁（patches/lan-access.patch + feature/lan-access 提交 diff）。

## 四、定案（写死，供以后参照）

- 主入口：`http://<host>:3081/`（完整功能）
- 备用/受限：`:3080`（对话可用，记忆配置走 3081）
- config-ui（配置界面）：默认 `:3083`（避让 3081；PORT 可覆盖）
- 软路由部署：沿用 3081 完整入口 + 3083 config-ui 方案（v0.2 落实，部署前再次核实双端口行为）
