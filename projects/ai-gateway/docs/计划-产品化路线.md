## 阶段1：部件固化

### 1.1 首批固化部件（推荐：P2 → P1 → P3）

| 顺序      | 部件             | 理由                                                                                     |
| --------- | ---------------- | ---------------------------------------------------------------------------------------- |
| **第1批** | P2 模型路由+监控 | 核心卖点；已有完整服务在跑；只需标准化路由策略+监控UI美化；独立验证周期短（1-2周）       |
| **第2批** | P1 综合面板      | 所有服务的聚合入口；P2 稳定后才值得美化展示；与 P2 并行可做（面板改 UI，不影响路由逻辑） |
| **第3批** | P3 Hermes 管理   | 开机自启+会话持久化；与 P4（dsh 接入）强耦合，但先独立固化其自身稳定性                   |

**不列入首批的理由**：

- P4 dsh 接入：依赖 Hermes 凭据（D3），前置阻塞
- P5 热备管理：需先完成换插实测（D5），且脚本自动化工作量较大
- P6/P7/P8：已有服务在跑，优先级低于 AI 核心能力
- P9/P10：锦上添花或阶段3之后

### 1.2 部件固化验收标准（通用模板，每部件套用）

每个部件"固化" = 同时满足以下所有条件：

| #   | 验收项            | 绿（通过）                                       | 红（不通过）                     |
| --- | ----------------- | ------------------------------------------------ | -------------------------------- |
| G1  | 代码/配置测试门禁 | 包内测试 100% 绿 + tsc 0 错 + oxlint 0 告警      | 任一测试失败或 typecheck 有错    |
| G2  | 提交记录          | 有独立 git commit（含 CHANGELOG 条目）           | 未提交                           |
| G3  | 真实环境稳定运行  | 连续 ≥7 天无崩溃/内存泄漏/服务中断               | 期间出现 1 次及以上崩溃          |
| G4  | 可重装复现        | U 盘换插或重新烧录后，服务自动恢复，无需人工干预 | 换插后需手工调试                 |
| G5  | 文档              | README 含功能说明+配置方法+故障排查              | 缺 README 或 README 与实现不一致 |

**分层 SKU**：

- 免费：基础镜像/教程——引流入口。
- 低：U 盘成品（几十~百元级）——仅引流钩子，低成本验证付费意愿。
- 中：成品 + 首启指导/远程部署（数百级）。
- 高：定制 + 长期运维订阅（数千~数万级）——主力价值所在，收益集中于此档。

**阶段5 验收**：文档站点上线；付费部署链路跑通（从下单到交付全流程 ≤24h）；首年订单 ≥10 笔。

## 端口段规划（dsh 308x 段）

**实测结论**：dsh web 实例（本机 PID 656011）同时监听 3080 与 3081；3081 为完整功能面（局域网全功能，含记忆/配置管理接口可读写——loopback-only 限制未套用，未受信来源实测亦直通 /api），3080 为受限对外面（/api 走 Host 信任围栏：回环与 --trusted-host 受信来源可读写，未受信来源一律 403——并非仅回环可写）。同实例同数据，无冲突。

**定案（2026-08-23 实测）**：

| 端口              | 用途                                               | 状态       |
| ----------------- | -------------------------------------------------- | ---------- |
| :3080             | dsh 受限对外面（对话可用；记忆/配置仅回环可写）    | 备用入口   |
| **:3081**         | **dsh 完整主入口（局域网全功能：对话+记忆+配置）** | **主入口** |
| :3083             | 配置 Web 界面（config-ui 默认，避让 3081）         | 配置       |
| :3082、:3084-3089 | 预留（未来 dsh 附加服务连续扩展）                  | 备用       |

注：软路由部署时 init 脚本需确认能否同样双端口（3080+3081）——待 v0.2 部署核实。
实测说明：3081 为 dsh 主进程第二监听（完整面）；config-ui 默认端口曾设 3081，与 dsh 完整入口撞车（3081 已被 dsh 占用，config-ui 无法监听），已改 3083 避让。

**避开软路由既有端口**：dsh 308x 段与已占用端口无冲突——模型路由网关 :9888、Hermes 管理/监控 :9119、文件服务 :5244 等（另有 :7000/:7681 等 Hermes 侧服务亦不重叠）；后续新增服务一律进 308x 预留段，不占用既有端口。
