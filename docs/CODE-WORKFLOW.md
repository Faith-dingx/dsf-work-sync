# 代码工作强制流程（防呆规范）

> 目的：从机制上防治模型做代码工作时的高频顽疾——
> ①丢三落四 ②大文件检索/修改困难 ③进死胡同不自知 ④陷细节忽略全局。
> 本规范是**强制流程**，不是建议。AGENTS.md 自动加载，所有代码工作必须遵守。

---

## P0 立项（全局优先，防丢三落四 + 防细节迷失）

1. **grill-me 拷问需求**：明确目标 / 边界 / 验收标准 / **不做什么**。
2. **writing-plans 写计划**，产出文档存入 `docs/`，必须包含：
   - 任务清单（可勾选，每任务一个验收标准）
   - 全局架构 / 文件结构 / 数据流（先立全局）
   - **文件改动清单**（新建/修改/删除，逐文件）
3. **铁律：计划未过用户确认，不写实现代码。**

## P1 实施（小步 + 快速验证，防死胡同 + 防大文件难）

1. **TDD 先行**：先写测试/接口定义，后写实现（需求被测试硬编码）。
2. **单步粒度**：一次只做 1 个任务。
3. **每步完成立即验证**：`npm run typecheck && npm run lint && npm test` —— **全绿才继续，否则停下修复**。
4. **大文件策略**（硬性）：
   - 新建文件 > 500 行 → 拆分成单一职责小文件。
   - 修改大文件 → **禁止全文加载**：先 `grep` 定位目标段 → `read` 带 offset/limit 只读该段 → `lsp` 找引用/定义 → 精确改。
5. **每 3~5 步回看计划**：勾选进度；发现偏离 → **停**，回正再继续。

## P2 验证（防遗漏 + 防死胡同）

1. **对照验收清单逐项验证**：每项都有**证据**（测试通过 / diff 确认），禁止"应该没问题"。
2. **`git diff` 完整审查**：确认覆盖计划内所有改动点，无未意图改动（防丢三落四）。
3. **subagent 独立代码评审**：让独立代理查遗漏 / 死胡同 / 过度工程（全局视角，防当局者迷）。

## P3 提交（机器门禁）

1. `husky pre-commit`：prettier + oxlint —— **不过不能提交**。
2. `husky pre-push`：vitest 全过 —— **不过不能推送**。
3. commit 信息用 **conventional commits** 规范（feat/fix/refactor/chore…）。

---

## 死胡同熔断（防"进死胡同不自知"）

- 同一方案**重试 ≥2 次仍失败** → 停止，换方案（不许自欺"再试一次"）。
- 连续 **2 轮无实质进展** → 停下，回看计划/重新评估（goal 任务设 max_goal_rounds 上限）。
- 卡住 > 15 分钟无输出 → **回滚到最近绿点**（git checkout），从干净状态重来。
- 方向不确定时，先跑**最小验证**（核心路径能否通），再全量实现。

## 全局护栏（防"陷细节忽略全局"）

- 每次动手前先读：README / 架构文档 / 本次计划（**先全局，后细节**）。
- **骨架先行**：先定接口/数据结构/模块边界，再填实现细节。
- **executing-plans review checkpoints**：每个阶段完成必须停下来检查整体是否符合计划。
