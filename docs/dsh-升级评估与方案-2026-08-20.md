# dsh 升级评估与方案（2026-08-20）

> 背景：用户要求查看 dsh 新版本，评估对我们之前修改的影响，制定更新方案。
> 结论：**最新版 rc.8（今天 8-20 发布，14 项更新）与我们的 lan-access 修改有 2 处文件冲突、1 处部署行为必须调整（--no-open），但配置/数据/插件全部兼容**。升级可行，需按方案分阶段执行。

---

| 分叉点       | 99f6f02fec                                                                    |

## 二、rc.8 更新内容（14 项，来源：官方 release + 智东西/36kr 报道 + 上游提交）

**新能力：**

1. 多模态正式补齐：DeepSeek 适配器可通过配置启用原生图片请求；具备视觉能力的模型直接送图
2. `/goal`、`/plan` 命令支持图文混合输入
3. 输入框 @ 菜单新增文件和会话引用
4. 纯文本模型工具层视觉兜底（OCR + 颜色统计 + 像素扫描 → 结构化证据给文本模型）——与我们的 vision-router 思路同源
5. Claude Code、Codex 作为 Profile Bundle 按需安装子代理；Codex 支持非交互权限模式 + 多个命名实例
6. Windows 持久 PowerShell PTY（与我们无关，Linux）

**修复/优化：** 7. 大图/历史累积图片过多导致请求失败 → 修复（新 `maxRequestImageBytes` + 超限转文本占位）8. 取消流式后已显示前缀不带到下一轮/分叉 → 修复 9. 自定义 OpenAI 兼容网关请求格式差异无法调用 + 推理内容回传缺失 → 修复（**对我们的 router-9888 直接利好**）10. web_search 支持并发查询（`queries` 数组）11. 子代理 reportDelivery 及时唤醒父任务 12. **`dsh web` 默认自动打开浏览器（`--no-open` 关闭）** 13. 大型历史会话分叉 + SQLite 读写性能优化（schema-17 物理块压缩）14. 参考输入/召回顺序对齐、模型选择器批量选择等 UI 完善

## 三、对我们之前修改的影响评估

### 3.1 lan-access 4 文件（冲突面逐文件）

| 文件                                      | 我们的改动                     | 上游改动                               | 影响                                                                           |
| ----------------------------------------- | ------------------------------ | -------------------------------------- | ------------------------------------------------------------------------------ |
| `packages/host/webserver/src/index.ts`    | host 类型 union→string         | **0 次**                               | ✅ 干净合并                                                                    |
| `packages/client/connection/src/index.ts` | privileged 方法用 trustedHosts | **0 次**                               | ✅ 干净合并                                                                    |
| `packages/bundle/web-app/src/startup.ts`  | 去掉 `--host 0.0.0.0` 禁令     | 加 `--no-open`/`openBrowser`（同文件） | ⚠️ **真冲突**。上游**仍拒绝 0.0.0.0**，必须保留我们的删除 + 接受上游 --no-open |
| `apps/web/src/main.ts`                    | randomUUID polyfill            | 2 次重构（注释/渲染器迁移）            | ⚠️ 注释区小冲突；polyfill 独立于重构，照常适用                                 |

**核心结论：上游 rc.8 仍未支持 LAN 绑定（0.0.0.0 依旧被 CLI 拒绝），我们的 lan-access 修改必须原样带过去，不是简单 pull。**

### 3.2 部署行为必须调整（升级前必做）

- **systemd 服务必须加 `--no-open`**：rc.8 默认 `dsh web` 自动开浏览器；我们的服务经 systemd 启动（非 SSH），会真的尝试在服务器上拉起浏览器。命令改为：
  `pnpm dsh web --host 0.0.0.0 --port 3080 --trusted-host ... --no-open`

### 3.3 配置/数据/插件兼容性（全部验证通过）

| 面                      | 验证结果                                                                                                                                                                                 |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| settings.yaml providers | 新 llm-pi-ai schema 仍接受 `api: openai-completions`/`apiKeyEnv`/`baseURL`/`models`/`displayName` ✅；我们未用 `compat`，不受 compat 字段收紧影响 ✅                                     |
| 持久化                  | 我们主存储 JSONL + session-query-sqlite 查询索引；rc.8 的 schema-17 只影响 `session-persistence-sqlite`（未启用），**我们的会话数据不受影响** ✅；session-query-sqlite 包 rc.8 无改动 ✅ |
| 插件                    | dsh-free-search@0.4.7、dsh-vision-router@1.6.2、dsh-persona-memory@0.2.0、dsh-auto-memory@0.1.28 的 peerDeps 均为 `^0.1.0-rc.6`/`>=0.1.0-rc.6`，**rc.8 满足范围，无需强制升级** ✅       |
| 视觉                    | 我们走 llm-pi-ai（router-9888 等），llm-deepseek 原生多模态不直接影响；rc.8 的 pi-ai 多模态修复（图超限转占位）对我们是净利好 ✅                                                         |
| 网关                    | rc.8 修复自定义 OpenAI 兼容网关差异 → router-9888 请求更稳（推理内容回传）✅                                                                                                             |

### 3.4 风险点

- 536 个提交的大跨度升级，除已知 2 文件冲突外，可能有未预见的行为变化（如 CLI/命令体系调整）
- rc.8 仍为预发布，可能存在新 bug（但同为 rc 系列，风险与我们当前部署同级）
- Agent Teams / 新子代理包名重构为实验性前缀，不影响我们的 tool-subagent 行（已验证 preset 用的是 tool-subagent-* 行）
