> 日期：2026-11-13 · 状态：**只读了解与对比，未执行任何迁移动作**
> 2 号机侧信息来源：本地归档 `dsh-archive/`（其现状权威描述）+ HTTP 实测端口探测；SSH 未授权，2 号机内部文件未逐一核对。

## 零、先说结论性差异（3 条）

1. **2 号机已经跑着一套 dsh 0.1.5**（3080 + 3083 在服务）——所以这次不是"从无到有"，而是**用 0.2.2 替换存量 0.1.5**，端口 3080/3083 会直接冲突。
2. **两代配置布局不同**：0.1.x 用 `settings.yaml` + `dsh.env`；0.2.2 用 `profiles/web/cordis.patch.yml` + `.credentials.yaml`，**0.2.2 体系里 settings.yaml / dsh.env 根本不存在**。存量配置不能直接搬，要转换。
3. **程序形态不同**：2 号机是**官方 npm 预编译包**（零改动）；本机是**源码仓 + tsx 源码模式**（11 个本地扩展插件）。迁 0.2.2 意味着要把源码 + 插件 + musl 原生件一起带过去。

## 三、迁移的技术难点（按文件存放位置展开）

1. **程序形态替换**：把 npm 预编译包换成源码 + 11 个本地扩展插件。软路由需能跑 `node --import tsx/esm`（tsx 依赖），或改为先 `pnpm build` 再跑编译产物。
2. **musl 原生件**：`node-pty` 官方 glibc 预编译在 musl 必崩 → 已有重编件 `dsh-archive/node-pty-musl-20260924/`（pty.node / spawn-helper / apply.sh）；`sharp` 需按 musl 换二进制（记忆：0.1.5 安装包曾因此启动即崩，v0.1.3 已补 musl 版）。
3. **procd 服务脚本重写**：现 `init.d-dsh` 按 0.1.5 的 `PKG_DIR=/mnt/agent/dsh/app/...` + `DSH_HOME=/srv/dsh/home` + `DSH_ENV_FILE=.../dsh.env` 写死；0.2.2 需指向源码仓、去掉 dsh.env、加载 cordis.patch.yml。
4. **配置代际转换**：2 号机 `settings.yaml`（7 provider，15.6K）里的 `llm-pi-ai.providers` 要搬进 0.2.2 的 `profiles/web/cordis.patch.yml` 的 `- id: llm-pi-ai` 段；`agent-default-model` / `permission` / `agent-presets` 顶层键在 0.2.2 同样进 patch 层。
5. **绝对路径全线重写**：guard 策略清单 `/home/dingx/DSF-work/docs/主agent可改写文件清单.yaml` 的 blacklist 全是 `/home/dingx/...`；preset 的 `filePolicyPath` 现为绝对路径 `/home/dingx/DSF-work/docs/...` → 迁到软路由须改成 `/mnt/hermes/dsh/...` 之类，否则 guard 换工作区即 fail-close 全拒（今日刚修过的问题）。
6. **9888 地址不用改**：定案刻意保留 `http://10.10.10.2:9888`，迁入后 dsh 自身即 10.10.10.2，局域网访问自身可达（08-25 检查清单已定）。
7. **config-ui 要同步今日修复**：2 号机那版 config-ui 是 keypool 改造版，尚未含今日 6 处修复（5.5 校验两级判定 + python stderr 屏蔽 + 路径统一）→ 迁 0.2.2 时一并同步，否则 3083 会重演 3200+ 条 sqlite 报错。
8. **数据随迁取舍**：`~/.dsh/sessions`（702M，含 738 个会话）、`~/.dsh/memory`（记忆库 + 白板）、`~/.dsh/storages`、`~/.dsh/models/js-semantic`（130M 语义模型，musl 需换版或改用远程检索）。
