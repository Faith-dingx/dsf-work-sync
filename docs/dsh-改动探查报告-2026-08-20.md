## 🟠 Bug #2（中危）：restart-dsh.sh 与 systemd 管理冲突，是"绊脚石"而非工具

- 当前 dsh 由 systemd user 服务 `dsh-web.service` 管理（`Restart=on-failure`，实测 13:23 由 systemd 启动）。
- `.temp/restart-dsh.sh` 用 `pkill` 杀 dsh → **会杀掉 systemd Main PID → systemd 自动重启一个新实例**；脚本 sleep 3 后又 `nohup` 自己启动一个 → **两个实例抢 3080 → EADDRINUSE**，且 nohup 实例**不受 systemd 管理**（失去自动重启 + 监控面板重启按钮）。
- 正确做法：重启用 `systemctl --user restart dsh-web.service`（或监控面板按钮），脚本应废弃/改写。

## 🟡 Bug #3（低危）：refresh-9888-models.py 两个健壮性缺口

1. `get_models_list()` 无 try/except：9888 不可达时整个脚本 traceback（cron 记错、退出码非 0）。虽不覆盖旧表，但无友好降级。
2. 探测法正则依赖 9888 错误消息 `可用: [...]` 格式：若格式变化，probe **静默返回 []** → 合并结果退化为 /v1/models 子集（48→8）→ **静默覆盖掉更全的旧表**。"失败不覆盖旧表"只保证硬失败，不保证静默退化。
3. 合并表同时含裸 id 与带前缀 id（/v1/models 返回裸、探测返回带前缀），而裸 id 已被 9888 废弃（400）——**表里有不可用条目，按表选模型会踩坑**。建议过滤裸 id 或标注。
