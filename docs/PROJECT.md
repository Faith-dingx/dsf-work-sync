# 项目目标：局域网统一管理 + 多方协作平台

> 这是**即将要做**的项目正文。新会话据此知道"接下来要做什么、往哪走"。
> 状态：**规划中**。技术方向已定，实施待布局细节确认。

## 一、项目愿景

以 dsh 为中枢，把**局域网内所有设备上的 agent**（本机 dsh、软路由 Hermes、
以及未来每台设备）和用户**统一到同一组会话里**，实现：
- **多方协作**：用户、dsh、Hermes（及更多 agent）能在同一对话里互通。
- **设备统一管理**：一个入口、统一能力，为长期稳定工作打底。

## 二、为什么做（背景）

- 用户的长期目标：让 dsh 成为稳定承载长期合作的载体（"你好"对话中已确立）。
- 当前痛点：每个会话/每个 agent 各自独立、互不相通；局域网设备分散。
- 用户希望："三方通话" + 未来每台设备的 agent 都能接入。

## 三、核心概念

**会话中枢（消息平台）**：一个共享的"频道 + 消息流"层，让所有参与方订阅同一会话。
- 用户：浏览器打开 Web 界面 → 发消息到频道。
- 本机 dsh：动态插件订阅频道，能读能回。
- 软路由 Hermes（及未来 agent）：通过适配器接入。
- dsh 承担"翻译/调度"角色，在参与方之间路由消息。

## 四、技术方案（方向）

- **载体**：Web 聊天界面 + 频道消息中枢（基于 dsh Web 基建，绑定局域网地址）。
- **会话层**：每个频道 = 一串消息（会话历史，可落盘）。
- **接入**：
  - 用户：Web UI。
  - dsh：动态 Cordis 插件订阅/读写。
  - Hermes：经其 CLI（`hermes chat`/`send`/`acp`）或 dashboard API 接入。
- **多设备复用**：把工具集 + 中枢做成可复制到局域网其他设备的机制。

## 五、架构草图

```
               ┌──────────────┐
  用户(浏览器) ─▶  会话中枢/Web  │
               │  (频道+消息流) │
               └───┬──────▲───┘
        dsh 插件 ───┘      │ Hermes(本机/软路由) / 未来agent
                      适配器(翻译/调度)
```
