# 记忆守卫插件（dsh-memory-guard）说明

> 2026-08-24 · 故障二防护实施
> 部署位置：`/home/dingx/deepseek-harness/packages/extensions/dsh-memory-guard/`

## 背景

故障二根因（2026-08-24 定案）：code-agent 子代理 efaf060d 调 `memory_log` 写今日日志时，
把**裸字面量** `{{commit}}` 写进记忆文件 → auto-memory 注入时模板插值器把 `{{commit}}`
当作模板变量引用，报 `UNKNOWN variable "{{commit}}"` 错误。

本插件在 **host 层给记忆写入加一道机器闸**：任何 memory 类工具的 payload 若含裸 `{{` / `}}`
字面量，一律拒绝，不让它进入记忆文件——从源头杜绝同一故障复发。

## 核心逻辑

### 1. 事件挂载（host 级，覆盖主 agent + 所有子代理）

```ts
export const inject = ['agents', 'tools']
ctx.on('tools/pre-execute', async (exec, next) => { ... })
```

与 `guard-main-agent` 同一事件机制（`tools/pre-execute`）。preset 中按
`- id: dsh-memory-guard / name: '@deepseek-ai/dsh-memory-guard'` 挂载时，
作用于 host 平面全体 agent，主 agent 与子代理一视同仁。

### 2. 拦截工具清单

- **写入类（默认拦截，11 个）**：`memory_log`、`memory_note`、`memory_user`、
  `memory_reflect`、`memory_consolidate`、`memory_maintain`、`memory_external`、
  `memory`（管理工具）、`calendar_add`、`calendar_done`、`calendar_remove`
- **只读类（5 个，默认不拦）**：`memory_read`、`memory_recall`、`memory_search`、
  `memory_status`、`calendar_list` —— 查询不落盘，不拦；配 `includeReadOnlyTools: true` 才拦
- `memory` 管理工具的只读 action（`read`/缺省）也放行，只在写 action（`add`/`update`/`rewrite`/`delete`）时检查

### 3. 检测 regex

```
\{\{[^}]+?\}\}|\{\{|\}\}
```

（源码常量 `DEFAULT_PATTERN = '\\{\\{[^}]+\\}\\}|\\{\\{|\\}\\}'`，可经 `pattern` 配置覆盖）

覆盖三种形态：

1. 完整模板字面量 `{{xxx}}`（故障形状）
2. 孤立左括号 `{{`
3. 孤立右括号 `}}`

### 4. 反引号转义豁免（关键语义）

`{{xxx}}` **被反引号包裹时放行**（如 ``写 `{{commit}}` 即可``）：这是故障定案认可的合法写法。
实现：对每个字符串字段值按反引号 `split`，只扫描偶数段（普通文本），奇数段（反引号内）跳过。

### 5. 字段级扫描（防 JSON 误伤）

**只遍历 args 树、逐个扫描字符串字段值，绝不扫描整段 JSON 字符串**。嵌套对象的 JSON
收尾自带 `}}`（如 `"]}}`），整段扫描会产生假阳性误拦——修复后的实现天然规避。

### 6. 拒绝语义

返回 `{ kind: 'deny', reason }`（pre-execute 的 deny 会物化为调用错误反馈给 agent），
reason 形如：

```
记忆禁止写 {{xxx}} 字面量 (工具 memory_log 检测到: "{{commit}}"; 参数路径: extra)，
请去掉花括号，或需要描述占位符时用反引号包裹（如 `{{commit}}` 而不是裸 {{commit}}）
```

- 给出检测到的样本（最多 3 个）+ 参数路径（如 `content.body[0]`），agent 能直接定位修正
- `ctx.logger.warn` 落结构化决策日志（matches/paths）

## 注册方式（二选一）

### A. 静态 preset 挂载（推荐，立即全局生效）

在 `~/.dsh/.agent-presets/full/agent.cordis.yml` 的 host 插件区追加：

```yaml
- id: dsh-memory-guard
  name: '@deepseek-ai/dsh-memory-guard'
```

（无 config 走默认：只拦写入类；需要拦只读查询加 `config: { includeReadOnlyTools: true }`）

### B. cordis_define 动态注册（运行时，不加源码包）

1. 读取 `cordis/host.js` 全文（去顶部注释）
2. `cordis_define`：`plugin.kind: "new"`、`idPrefix: "memg"`、`name: "dsh-memory-guard"`、
   `purpose` 简述，`code.host` = host.js 内容
3. `cordis_run` 激活（host 半体，无 client half）
4. 注意：`cordis_define` **只保存不激活**，必须显式 `cordis_run`

## 边界与注意

- 只拦**裸**字面量；反引号包裹是合法转义通道，不会被拦
- 只读查询默认不拦（不写盘、不产生注入风险），需要更严格可开配置
- deny 报错本身含 `{{xxx}}` 字样——它进入对话上下文但不落记忆文件，无二次注入风险
- 插件纯拦截不改写 payload；不 undo 已写入的历史脏数据（故障二的既有 line 22 已另修）
