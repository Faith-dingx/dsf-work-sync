## 三、一键适配脚本用法（1a）

```bash
# 预览（不写入、不备份）
bash scripts/adapt-machine-paths.sh /srv/dsh/DSF-work 10.10.10.10 --dry-run

# 实际执行（迁移后在新机器上）
bash scripts/adapt-machine-paths.sh /srv/dsh/DSF-work 10.10.10.10

# IP 不变时
bash scripts/adapt-machine-paths.sh /srv/dsh/DSF-work --keep-ip
```

行为：

1. 改写 `docs/主agent可改写文件清单.yaml`（5 处 value 前缀 → 新工作区路径）
2. 依据本机 systemd 单元打印 dsh-web/config-ui 新版片段（HOME/路径/IP 已替换；**不写盘、不执行 systemctl**）
3. 改写 `scripts/build-dsh-router-package.sh` 的 WORKSPACE/HARNESS_DIR 两行
4. 每个被改写文件改前备份 `*.bak-适配-<时间戳>`
5. 全程 diff 摘要；`--dry-run` 只预览

可移植性：脚本自身旧值可用 `OLD_WORKSPACE/OLD_HOME/OLD_HARNESS/OLD_IP1/OLD_IP2`、新值可用
`NEW_HOME/NEW_HARNESS/NEW_IP1/NEW_IP2` 环境变量覆盖，默认值按本机标准布局回退，不硬编码。

### service 单元模板（1b）

`docs/service单元模板/`：两个 `*.template`（占位符为 HOME / HARNESS_DIR / WORKSPACE / TRUSTED_HOSTS）+ README。
迁移时复制到新机器 `~/.config/systemd/user/` 后 sed 替换占位符 → `systemctl --user daemon-reload`
（systemd 重载是迁移时的用户操作，本脚本与文档均不执行）。

### 打包脚本参数化（1c）

```bash
WORKSPACE="${WORKSPACE:-/home/dingx/DSF-work}"
HARNESS_DIR="${HARNESS_DIR:-/home/dingx/deepseek-harness}"
```

默认值不变（本机运行零影响）；迁移时 `WORKSPACE=/srv/dsh/DSF-work HARNESS_DIR=/srv/dsh/deepseek-harness bash scripts/build-dsh-router-package.sh` 即可。

## 四、云端备份架构

三层备份，按"介质先行、敏感加密"组织：

```
┌─ 代码层（云端 ✓）────────────────────────────────────────────┐
│ deepseek-harness  →  fork: feature/lan-access（6 commit 已 push）│
└──────────────────────────────────────────────────────────────┘
┌─ 文档/工作区层（介质先行）───────────────────────────────────┐
│ DSF-work  →  git bundle（.temp/backup-20260825/dsf-work-*.bundle）│
│             可上传任意云端/网盘；git clone <bundle> 即恢复       │
│             后续演进：推私有仓 dsf-work-sync（GitHub）            │
└──────────────────────────────────────────────────────────────┘
┌─ 敏感层（gpg 加密）───────────────────────────────────────────┐
│ settings.yaml / .credentials.yaml / ~/.dsh/memory /           │
│ ~/.dsh/sessions/query.sqlite                                  │
│   → tar czf - ... | gpg -e -r "DSF-backup"                    │
│     （密钥仅存本机 gpg 环，不随加密包走）                        │
└──────────────────────────────────────────────────────────────┘
```

### bundle 与加密包的 MANIFEST 记录

- `full-20260825-155936/MANIFEST.txt`（全量快照）+ 本轮新增条目（bundle / gpg 加密包，附 sha256 + 字节数）

## 五、三类备份的恢复步骤

### 5.1 代码层（harness）

```bash
git clone https://github.com/<fork>/deepseek-harness.git
cd deepseek-harness && git checkout feature/lan-access
# 回退/版本对照可用 rollback.sh harness（详见 /home/dingx/bin/rollback.sh）
```

### 5.2 文档/工作区层（DSF-work）

```bash
# 从 bundle 恢复（无需网络）
git clone /path/to/dsf-work-2026-08-25.bundle DSF-work
cd DSF-work && git remote remove origin   # bundle 克隆后清理源 remote
# 或未来从私有仓：git clone git@github.com:.../dsf-work-sync.git
```

### 5.3 敏感层（settings/credentials/记忆）

```bash
gpg -d dsh-sensitive-<date>.tar.gz.gpg | tar xzf - -C ~/   # 解开到 ~/.dsh/ 对应位置
# 验证（只列文件名，不打印内容）：
gpg -d dsh-sensitive-<date>.tar.gz.gpg | tar tzf -
```

> 密钥：本机 `gpg --list-keys DSF-backup` 可见；**密钥仅存本机 gpg 环，不随加密包走**。
> 若密钥丢失，加密包无法解密 —— 迁移前先在新机器导入私钥（`gpg --import`）。

## 六、遗留风险与说明

1. **1a 脚本未覆盖**：yaml 静态注释示例行（41/48 行）与历史 reason（35 行）不改 —— 属有意为之；
   config-ui 的 `server.js` 与 `refresh-9888-models.py` 存在 `/home/dingx` 硬编码（server.js 已有
   `HARNESS_DIR/ROLLBACK_HARNESS_DIR` 环境变量兜底，rollback 与模型目录可自动适配；
   refresh-9888-models.py 两行输出路径在 `.temp` 下，不阻塞运行，迁移时若使用需手工改）。
2. **service 片段未写盘**：迁移时必须在新机器上先落盘再 `daemon-reload`（用户操作）。
3. **gpg 密钥容灾**：无口令密钥便利但风险集中，建议迁移后补一次 `gpg --export` 的离线备份。
4. **bundle 不含未提交改动**：`--all` 只打包已提交历史；本轮新增文件（脚本/模板/手册）已在
   `docs/` 与 `scripts/` 落盘，随下一次 commit 进入后续 bundle；本机工作区本身即最新来源。
